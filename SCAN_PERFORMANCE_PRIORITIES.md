# Scan Performance Priorities

Consider the following improvements. These are in priority order.

| Priority | Improvement | Where | Implementation |
|---|---|---|---|
| 1 | Bulk package/atomic summaries | [AtomicDirectoryParallelSummary.swift](/Users/colin/Programming/Radix/Radix/Services/AtomicDirectoryParallelSummary.swift:259), [AtomicDirectorySummaryWalker.swift](/Users/colin/Programming/Radix/Radix/Services/AtomicDirectorySummaryWalker.swift:40) | Replace `FileManager.enumerator` and per-child `resourceValues` with a recursive `getattrlistbulk` work queue. Inside a known package, package detection can be disabled because nested packages are already traversed as directories. This is the clearest remaining improvement for Xcode, Outlook, caches, and generated trees. |
| 2 | Eliminate most package-property lookups | [BulkDirectoryEnumerator.swift](/Users/colin/Programming/Radix/Radix/Services/BulkDirectoryEnumerator.swift:271), [ScanMetadataLoader.swift](/Users/colin/Programming/Radix/Radix/Services/ScanMetadataLoader.swift:279) | Bulk enumeration still calls `.isPackageKey` for every directory. Introduce a cached `PackageClassifier` with conservative fast negatives and only consult Foundation for plausible or ambiguous package directories. Preserve fallback behavior for unusual extensionless packages. |
| 3 | Reuse atomic-probe traversal | [AtomicDirectorySummarizer.swift](/Users/colin/Programming/Radix/Radix/Services/AtomicDirectorySummarizer.swift:25), [AtomicDirectorySummaryProbe.swift](/Users/colin/Programming/Radix/Radix/Services/AtomicDirectorySummaryProbe.swift:217) | A speculative probe can inspect thousands of entries and then the summarizer walks them again. Return accumulated sizes, identities, warnings, and an resumable enumeration cursor from the probe so a successful atomic summary continues rather than restarts. |
| 4 | Stream bulk enumeration batches | [BulkDirectoryEnumerator.swift](/Users/colin/Programming/Radix/Radix/Services/BulkDirectoryEnumerator.swift:26) | The syscall is batched, but Radix materializes every immediate child into one array. Add a cursor/callback API that yields parsed batches. Probes could stop immediately at their threshold, and very wide directories would use less memory and begin processing sooner. |
| 5 | Share package-summary concurrency globally | [ScanEngine.swift](/Users/colin/Programming/Radix/Radix/Services/ScanEngine.swift:793), [AtomicDirectoryParallelSummary.swift](/Users/colin/Programming/Radix/Radix/Services/AtomicDirectoryParallelSummary.swift:184) | Package roots are effectively summarized one at a time, with a fresh internal task group per package. Use one scan-wide bounded summary pool that accepts work from multiple packages. This would keep workers busy across small bundles without multiplying concurrency or overwhelming storage. |
| 6 | Improve package-summary progress | [ScanProgress.swift](/Users/colin/Programming/Radix/Radix/Models/ScanProgress.swift:10), [AtomicDirectoryParallelSummary.swift](/Users/colin/Programming/Radix/Radix/Services/AtomicDirectoryParallelSummary.swift:196) | Package heartbeats mostly update the displayed path, leaving progress around 1%. Track package-local visited items and estimated remaining work, then fold that into traversal progress. This does not shorten the scan, but it prevents Xcode or Outlook from appearing stuck. |
| 7 | Incremental rescans with FSEvents | [ScanCoordinator.swift](/Users/colin/Programming/Radix/Radix/Services/ScanCoordinator.swift), [ScanEngine.swift](/Users/colin/Programming/Radix/Radix/Services/ScanEngine.swift) | Store the volume identity and FSEvents event ID with completed scans. On rescan, enumerate changed subtrees, splice replacements into the previous `FileTreeStore`, and rebuild affected ancestors. Fall back to a full scan after event gaps, settings changes, or volume changes. This is a larger feature but offers the biggest improvement for repeated scans. |
| 8 | Compact tree/path storage | [ScanEngine.swift](/Users/colin/Programming/Radix/Radix/Services/ScanEngine.swift:648), [FileTreeStore.swift](/Users/colin/Programming/Radix/Radix/Models/FileTreeStore.swift:165) | Full scans retain many duplicated path strings and dictionary keys. Move toward integer node IDs, parent-relative names, and an arena-style node store. Materialize full URLs only for display or file actions. This primarily reduces memory pressure and finalization time on multi-million-node scans. |
| 9 | Online hard-link accounting | [HardLinkDeduplicator.swift](/Users/colin/Programming/Radix/Radix/Services/HardLinkDeduplicator.swift:31) | Instead of collecting every `HardLinkClaim` and correcting totals afterward, maintain a scan-wide identity owner table and account for duplicates as results arrive. This removes a final pass and claim storage, though the benefit depends heavily on the filesystem contents. |
| 10 | Descriptor-relative native traversal | [BulkDirectoryEnumerator.swift](/Users/colin/Programming/Radix/Radix/Services/BulkDirectoryEnumerator.swift:35), [ScanEngine.swift](/Users/colin/Programming/Radix/Radix/Services/ScanEngine.swift:749) | The ambitious endpoint is a native walker using `openat`/directory descriptors and raw names, delaying `URL` and full-path creation. It would reduce repeated path resolution and Foundation allocation, but it is a substantial rewrite with more error-handling and filesystem-compatibility risk. |

My recommended sequence would be **1 → 3/4 together → 2 → 5**. Those remain incremental enough to preserve Radix’s semantics while attacking known hot paths. Incremental rescans would be the best larger product investment afterward. When you implement, if 2-4 subagents would make the process faster or higher quality, use them.

I would not prioritize raising traversal worker counts, rewriting finalization again, or further optimizing ordinary exclusion matching—the recent work has already addressed those areas, and extra concurrency could worsen I/O contention.
